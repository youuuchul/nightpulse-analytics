## 1. 퍼널 탭 재구성 (결정 2026-09-23)

- **무엇을**: '탐색' 탭을 **'퍼널'** 탭으로 바꾼다. 본체 = 퍼널 분석, 보조 = 탐색 도달률·요일×시간대. '공간별' 보기는 '행사·결제' 탭으로 옮긴다.
- **왜**: 지금 탐색 탭의 타일 3개(탐색 도달률·행사 상세 조회율·신청 화면 도달률)가 이미 퍼널 단계 도달률이라, 탭 이름이 내용을 가리키지 않았다. 퍼널 스냅샷 막대 하나로는 "어느 단계가 언제부터, 어느 집단에서 나빠졌는가"를 못 본다.
- **어디에**: `dashboard/src/tabs/FunnelTab.tsx`(신설, 탐색 탭 대체). 마트 변경 없음 — `funnel_daily`(일 × 단계 × 세그먼트 3축)로 화면 계산.
- **구성**
  - 스코어보드: 전체 전환율(랜딩→결제) · 최대 이탈 단계(단계명과 −%p) · 직전 기간 대비
  - 메인 차트: 단계 전환율 주별 추이(상세→신청 화면, 신청 화면→결제)
  - 표: 세그먼트별 퍼널 비교(행 = 채널·플랫폼·회원 값, 열 = 단계 도달률, 셀 히트맵)
  - 드릴다운 1 **오디언스별 퍼널** — §2
  - 드릴다운 2 **경로 탐색** — §3
  - 보조: 요일×시간대 히트맵(기존)
- **완료 기준**: 필터 4축이 모든 카드·표·드릴다운에 실제로 적용된다. 탭 6개 유지. 캡처 라이트·다크.

## 2. 오디언스별 퍼널 (드릴다운)

- **무엇을**: 행동 조건으로 묶은 사용자 그룹(오디언스)별로 5단계 도달률을 나란히 본다. 세그먼트(채널·플랫폼·회원)는 사람의 속성이고, 오디언스는 **그 기간의 행동**으로 정하는 그룹이라 축이 다르다.
- **오디언스 정의(사람 × 주 단위 판정, 서로 겹칠 수 있음)**

| id | 이름 | 조건 |
|---|---|---|
| `new` | 신규 | 그 주가 첫 방문 주 |
| `returning` | 재방문 | 이전에 방문한 적 있음 |
| `paid_inflow` | 광고 유입 | 그 주 세션 중 유료 채널 라스트클릭 1회 이상 |
| `past_payer` | 결제 경험 | 그 주 이전에 결제 1회 이상 |
| `apply_no_pay` | 신청 후 미결제 | 그 주 이전 신청 있음, 결제 없음 |
| `explorer_only` | 탐색만 | 그 주 상세 조회 있음, 신청 화면 없음 |

- **마트**: `marts.weekly_audience_funnel` — 그레인 주 × 오디언스 × 단계 × 세그먼트 3축. 열 `week_start, audience_id, step, channel1, device_platform, member_seg, persons`. 단계는 `funnel_daily`와 같은 5개(누적 조건). 원천 `staging.int_person_day` + `int_session`.
- **화면**: 오디언스 선택 칩(다중) → 오디언스 × 단계 도달률 표 + 선택 오디언스의 주별 전환율 추이.
- **완료 기준**: 같은 주의 `new`+`returning` persons 합 = `weekly_activity.wau`(대조 항목 C6 추가).

## 3. 경로 탐색 (드릴다운)

- **무엇을**: 세션 안에서 화면이 어떻게 이어지는지(랜딩 → 2단계 → … → 5단계) 생키 다이어그램. GA4 탐색의 경로 탐색과 같은 읽기.
- **마트**: `marts.weekly_path` — 그레인 주 × 세그먼트 3축 × 단계(1~5) × from 화면 × to 화면. 열 `week_start, channel1, device_platform, member_seg, step, from_screen, to_screen, sessions`. 화면은 `screen_name`(NightPulse 화면 체계), 세션당 앞 5개 화면 전이만, 자동 로드 세션 제외. 상위 화면 12개 밖은 `(기타)`로 접어 노드 수를 고정한다. 원천 `staging.events_clean`.
- **화면**: 시작 화면 선택(기본 전체 랜딩) → 단계별 노드·링크 생키(노드 최대 12 × 5단계), 링크 클릭 시 그 경로의 세션 수·비중. 이탈은 각 단계에 `(이탈)` 노드로 표시.
- **완료 기준**: 1단계 세션 합 = 그 주 방문 세션 수(`weekly_activity` 세션 합, 대조 C7).

## 4. 소개 페이지 (포트폴리오 입구)

- **무엇을**: 대시보드 헤더에서 여는 별도 페이지 `/about`. 탭이 아니다 — 대시보드는 그대로 두고 맥락만 준다.
- **구성**
  1. 한 문장 요약 + "합성 데이터" 표기
  2. 가상 프로덕트 배경(NightPulse: 공간·행사 탐색 → 신청 → 결제. 회원·비회원, 앱·웹, 광고 유입) 한 단락
  3. 핵심 퍼널 5화면 와이어프레임(단순 SVG 목업: 홈/지도 → 행사 상세 → 로그인·가입 → 신청 화면 → 결제 완료), 각 화면 아래 발생 이벤트명
  4. 데이터 흐름 도식(GA4형 로그 + RDB 스냅샷 + 광고 리포트 → raw → staging → marts → ops → data.json → 정적 웹)
  5. 지표·설계 문서 링크(`docs/architecture.md` `docs/metrics.md` `docs/dashboard.md`), 저장소 링크
- **왜**: 포트폴리오 방문자가 30초 안에 "무슨 서비스의 무슨 데이터를 어떻게 다뤘는지" 잡게. 대시보드 안에 설명 문장을 넣지 않기 위한 자리.
- **완료 기준**: 폰 폭에서 읽히고, 대시보드 헤더 링크 왕복이 URL 상태를 잃지 않는다.

## 6. 헤더 정리·데이터 페이지 (결정 2026-09-23 저녁)

- **무엇을**: ① 헤더 왼쪽에 페이지 이동 `프로젝트 개요`·`데이터`, 오른쪽에 기준일·저톤 데이터 설명 문장·테마. '합성 데이터' 뱃지 제거. ② 개요 페이지 상단 뱃지도 문장으로. ③ `데이터` 페이지 신설 — 층별 표 목록과 스키마·미리보기.
- **왜**: 대시보드의 맥락(목적·배경·시나리오·파이프라인)이 뱃지보다 중요하다. "합성 데이터"는 용어가 낯설어 문장으로 풀어야 한다. 마트 스키마와 실제 행을 포트폴리오 안에서 바로 볼 수 있어야 파이프라인 설계가 증명된다.

## 7. 개요 탭 — KPI별 추이 카드 (결정 2026-09-23 저녁)

- **무엇을**: 개요 탭 스코어보드 아래에 핵심 KPI별 추이 카드를 **차례로** 쌓는다(방문자 → 활성 사용자 → 신규·가입 → 신청·결제 → 결제 금액). 지금은 방문자 추이 하나뿐이다.
- **카드 구성(공통 컴포넌트 `TrendCard`)**
  - 왼쪽 차트: 현재 기간 실선 + **직전 기간 점선**(같은 길이, 같은 x 위치에 겹침). 그레인 토글 `자동 · 일 · 주 · 월`(자동 = 기간 길이에 따라: 7일 이하 일, 28~90일 주, 그 이상 월. 1일이면 시간별).
  - 마우스오버 툴팁: `날짜(요일)` / `지표명: 값` / `전기 대비 ▲▼ %` / `전기 날짜: 값`. 세로 가이드선, 툴팁은 차트 안에서 위치 보정.
  - 오른쪽 분해 타일: 그 KPI를 세그먼트 한 축으로 쪼갠 값 3개(기본 회원/비회원 + 전체, 각각 전기 대비 %). 분해 축 선택기(회원 · 채널 · 플랫폼)는 카드 머리에 작은 세그먼트 컨트롤. 세그먼트 필터가 이미 걸려 있으면 그 축은 선택기에서 비활성.
  - 카드 머리: 지표명 · 그레인 라벨 · 기간·전기 범위 한 줄(`8/24~9/20 · 전기 7/27~8/23`).
  - **기간 드릴다운**: 차트의 점(또는 막대)을 클릭하면 그 버킷으로 기간이 바뀐다(주 → 그 7일, 월 → 그 달, 일 → 그날 1일 시간별). URL 상태(직접 기간)로 반영되어 뒤로 가기로 복귀.
- **어디에**: `dashboard/src/components/TrendCard.tsx`, `src/tabs/Overview.tsx`. 데이터는 `daily_metrics`(세그먼트 3축)·`hourly_metrics`로 화면 계산. 마트 변경 없음.
- **왜**: 개요는 "지금 어떤지 + 언제부터 그런지"를 한 화면에서 답해야 한다. 타일만으로는 추이가 없고, 추이 하나로는 KPI 간 관계가 안 보인다.
- **완료 기준**: 필터 4축·그레인·분해 축이 모든 카드에 실제로 적용. 1일 선택 시 시간별 차트로 전환. 전기가 없는 기간(1년)은 점선·전기 대비를 숨기고 라벨에 `전기 없음`. 캡처 라이트·다크·폰.

## 8. 사람 단위 지표를 기간 고유 수로 (결정 2026-09-23 밤)

- **무엇을**: 사람 단위 지표(방문자·활성 방문자·상세 조회·신청 화면·결제자 등)를 어떤 기간·필터에서도 **기간 고유 사람 수**로 센다. "일평균"·"명·일" 표기를 전부 없앤다. 건수 지표(세션·신청·결제·금액)는 합, 신규·가입은 합(사람당 1회라 고유와 같음).
- **왜**: 일별 고유 수를 더하면 사람·일이 되고, 평균을 내면 옆 칸의 합과 어긋난다. 개요 탭에서 방문자 일평균 323 옆에 신규 356이 놓이는 식의 혼선이 생겼다.
- **마트**: `marts.person_day` — 그레인 사람 × 일. 열 `person_key INT64`(익명 정수 키, `DENSE_RANK` 로 재부여 — 원본 id 없음) · `kst_date` · `channel1` · `device_platform` · `member_seg` · `flags INT64`(비트: 1 visited · 2 explored · 4 event_detail · 8 detail_any · 16 signed_up(그날) · 32 logged_in · 64 apply_view · 128 applied · 256 paid · 512 cancelled · 1024 searched · 2048 banner · 4096 shared · 8192 multi_session · 16384 first_visit). 원천 `staging.int_person_day`. 대조 C8: 일별 `visited` 고유 수 = `daily_metrics.persons` 합(세그먼트 포함).
- **추출**: `data.json` 키 `person_day` — 열 배열 형식으로 압축 `{"cols": ["pk","d","c","p","m","f"], "rows": [[…], …]}` (d 는 기준일로부터 일수 정수, c/p/m 은 코드표 인덱스). 목표 3MB 이하.
- **화면 규칙**: 사람 지표 타일·분해 타일·전기 대비는 `person_day` 로 기간 고유 계산. 일별 추이는 일별 고유(마트 값)로 그대로. 주·월 버킷 추이는 버킷 고유 사람. 툴팁·라벨 단위는 `명`, 건수는 `건`·`원`.
- **완료 기준**: 개요 28일 방문자(고유) ≥ 신규 방문자, 어떤 필터에서도 타일 값 = BigQuery `COUNT(DISTINCT person_id)` 대조(검증 문서 `docs/reconciliation_dashboard.md` 에 5개 조합 기록). "일평균"·"명·일" grep 0건.

- **기준일 현황에 행사 수**: `dim_event` 일정(시작·종료)을 `daily_event` 또는 별도 소형 키로 내보내 진행 중/예정 행사 수 표시
- **부분 버킷 표시**: 주·월 버킷의 마지막 짧은 구간을 흐리게(또는 라벨에 일수) 표시할지

- `data.json` 분할 로딩(현재 18MB, gzip 614KB — 탭별 파일로 나눠 첫 화면 시간 단축)
- 월간 브리핑 자동 문장(월간 요약 표의 수치를 3줄 요약으로 — 규칙 기반, LLM 없이)
- 코호트 히트맵 월 단위 전환·세그먼트 비교 보기
- 파이프라인 예약 실행 예시(예약 쿼리 SQL 결합본 생성기)와 실패 알림 설계 문서
